1. PARTIAL FUNCTION ATTRIBUTE ERROR
   ─────────────────────────────────────────────────────────────────────────
   File: python-backend/server.py
   Location: Line 274 (in _record_events method)
   
   Error: AttributeError: 'functools.partial' object has no attribute '__code__'
   
   Root Cause:
   - Handoff handler's `on_invoke_handoff` is a functools.partial object
   - Code attempted to access `__code__` attribute directly on partial
   - functools.partial doesn't expose __code__, it wraps the actual function
   
   Fix Applied:
   - Added type checking to detect partial functions
   - Added logic to access `.func` attribute for wrapped functions
   - Added try-catch with graceful fallback
   - Logs debug info if extraction fails instead of crashing
   
   Code Changes:
   BEFORE:
   ```
   fn = ho.on_invoke_handoff
   fv = fn.__code__.co_freevars  # CRASHES on partial!
   cl = fn.__closure__ or []
   ```
   
   AFTER:
   ```
   fn = ho.on_invoke_handoff
   try:
       code = getattr(fn, "__code__", None)
       if code is None and hasattr(fn, "func"):
           code = getattr(fn.func, "__code__", None)
       if code:
           fv = code.co_freevars
           cl = fn.__closure__ or (getattr(fn, "func", fn).__closure__ or [])
           # ... process handoff info
   except Exception as e:
       logger.debug(f"Could not extract handoff callback info: {e}")
   ```


2. INVALID GUARDRAIL MODEL NAME
   ─────────────────────────────────────────────────────────────────────────
   File: python-backend/airline/guardrails.py
   Location: Line 14
   
   Error: Model "gpt-4.1-mini" doesn't exist (invalid OpenAI model name)
   
   Root Cause:

   - This is the current recommended small model for guardrail tasks
   
   Code Changes:
   BEFORE:
   ```
   GUARDRAIL_MODEL = "gpt-4.1-mini"
   ```
   
   AFTER:
   ```
   GUARDRAIL_MODEL = "gpt-4o-mini"
   ```


3. SILENT GUARDRAIL FAILURES - RELEVANCE GUARDRAIL
   ─────────────────────────────────────────────────────────────────────────
   File: python-backend/airline/guardrails.py
   Location: Lines 42-51 (relevance_guardrail function)
   
   Error: Guardrail errors would crash the entire stream without logging
   
   Root Cause:
   - No error handling in guardrail runner
   - Any exception in guardrail evaluation would propagate and terminate stream
   - No fallback logic to allow conversation to continue
   
   Fix Applied:
   - Added try-catch wrapper around guardrail execution
   - Logs exception with full details
   - Returns safe fallback output (message is relevant, no tripwire)
   - Allows message through rather than blocking on error
   
   Code Changes:
   BEFORE:
   ```
   @input_guardrail(name="Relevance Guardrail")
   async def relevance_guardrail(...):
       result = await Runner.run(guardrail_agent, ...)  # No error handling!
       final = result.final_output_as(RelevanceOutput)
       return GuardrailFunctionOutput(...)
   ```
   
   AFTER:
   ```
   @input_guardrail(name="Relevance Guardrail")
   async def relevance_guardrail(...):
       try:
           result = await Runner.run(guardrail_agent, ...)
           final = result.final_output_as(RelevanceOutput)
           return GuardrailFunctionOutput(output_info=final, ...)
       except Exception as e:
           logger.exception(f"Relevance guardrail failed: {e}")
           return GuardrailFunctionOutput(
               output_info=RelevanceOutput(
                   reasoning=f"Error evaluating relevance: {str(e)}", 
                   is_relevant=True
               ),
               tripwire_triggered=False  # Allow through on error
           )
   ```

5. MODELREFUSALERROR NOT CAUGHT IN STREAMING LOOP
   ─────────────────────────────────────────────────────────────────────────
   File: python-backend/server.py
   Location: Lines 23, 427-441 (respond method)
   
   Error: ModelRefusalError from guardrail evaluation crashes the stream
   
   Root Cause:
   - ModelRefusalError wasn't imported or specifically handled
   - Was only caught by generic Exception handler
   - Prevents proper error messaging to client
   
   Fix Applied:
   - Added ModelRefusalError to imports (line 24)
   - Added specific exception handler before generic Exception handler
   - Provides user-friendly error message
   - Logs full exception details for debugging
   
   Code Changes:
   BEFORE (Line 23):
   ```
   from agents.exceptions import MaxTurnsExceeded
   ```
   
   AFTER (Line 24):
   ```
   from agents.exceptions import MaxTurnsExceeded, ModelRefusalError
   ```
   
   Added new exception handler (Lines 427-441):
   ```
   except ModelRefusalError as err:
       logger.exception(f"Guardrail model error (possible invalid model name): {err}")
       error_message = "I encountered a temporary issue. Please try again."
       state.input_items.append({"role": "assistant", "content": error_message})
       try:
           yield ThreadItemDoneEvent(
               item=AssistantMessageItem(
                   id=self.store.generate_item_id("message", thread, context),
                   thread_id=thread.id,
                   created_at=datetime.now(),
                   content=[AssistantMessageContent(text=error_message)],
               )
           )
       except Exception as yield_err:
           logger.exception(f"Failed to send error message to client: {yield_err}")
       return
   ```
